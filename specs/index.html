RFID Album Cover

A static web page that turns album covers, images and emoji into printable stickers for ISO-size RFID cards, such as the cards used with a Phoniebox.

Goals

  • Find an album's cover art and its artist and title by searching, upload any image, or pick an emoji.
  • Generate an A4 PDF of portrait stickers at exact physical size, ready to print and cut with a paper trimmer.
  • Run entirely in the browser. No server and no account.

Non-goals

  • Playing music, or linking cards to music. Phoniebox does that.
  • Reading or writing RFID tags.
  • Saving cards between sessions. Closing the tab discards the card list.
  • Card formats other than ISO ID-1, stickers with rounded corners, and cutting plotters.
  • Languages other than English.

Glossary

TermMeaning
CardPhysical RFID card, ISO/IEC 7810 ID-1: 54 × 85.6 mm, used upright (portrait).
Card entryOne item in the card list: an image, a crop, an artist and a title. Becomes one sticker.
StickerThe printed rectangle stuck on a card. It has square corners and is smaller than the card by the inset on every side.
InsetDistance between the card edge and the sticker edge. A setting with a default of 1.5 mm.
Art areaThe square at the top of the sticker that shows the cropped image.
Text areaThe strip below the art area, 31.6 mm high, with the artist and title.
SheetOne A4 PDF page holding up to 9 stickers in a tight 3 × 3 grid, with cut marks.

How it works

flowchart LR
  S[Search box] -->|term| I[(iTunes Search API)]
  I -->|albums + art URLs| R[Results]
  R -->|pick| L[Card list]
  U[Image upload] --> C[Crop dialog]
  C --> L
  E[Emoji picker] -->|pick| L
  L -->|edit text / re-crop / remove| L
  L --> P[PDF generator]
  P --> D[rfid-cards.pdf download]

All processing happens in the browser. The only requests to other sites go to the iTunes Search API and Apple's artwork server. Both send Access-Control-Allow-Origin: *. The emoji graphics come from the app's own site.

Features

  • Search: find albums on iTunes and add them as card entries.
  • Upload and crop: add any image and choose the square part to show.
  • Emoji: pick an emoji, drawn large and centred.
  • Card list: preview, edit text, re-crop, remove; text fitting and warnings.
  • Sticker sheet PDF: sticker size, inset setting, sheet layout, cut marks, PDF download.

UI mocks

  • App: the single page, with the crop dialog.
  • Printed sheet: the A4 PDF page, with dimensions.

Architecture decisions

  1. Static, client-only app on GitHub Pages
  2. Tech stack: TypeScript, Vite, Svelte, pdf-lib
  3. iTunes Search API as the only online source
  4. Sticker geometry: portrait, square corners, configurable inset
  5. Generate the PDF in the browser
  6. Session-only state
  7. Bundled Noto Emoji

Quality requirements

  • Browsers: current Chrome, Firefox and Safari on desktop.
  • Privacy: no analytics and no cookies. Images and text never leave the browser. Search terms go to Apple only.
  • Fidelity: the on-screen sticker preview and the PDF use the same font and the same text-fit result.
  • Documentation: a concise README.md covering what the tool does, how to print (at 100 % / actual size), and the developer workflow. Code comments only where the reason isn't obvious.
  • Tests: unit tests for geometry, text fitting and PDF layout. Playwright e2e tests cover every feature and every acceptance criterion; each test names the AC-… IDs it covers. E2E tests stub the iTunes API and artwork with fixtures and never call Apple.

Developer workflow

The project provides these Taskfile commands:

CommandDoes
task buildType-check and build the static site into dist/.
task runStart the Vite dev server.
task lintRun the linters and the formatter check.
task testRun the unit tests.
task e2eRun the Playwright e2e tests against a production build.
task specServe ./specs locally (python3 -m http.server 8000 -d specs). Not part of check.
task checkRun build, lint, test and e2e, and fail if any of them fails. This is the pre-commit gate.

A GitHub Actions workflow runs task check on every push. On main, it also deploys dist/ to GitHub Pages.
