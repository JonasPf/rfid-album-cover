ADR 0003: iTunes Search API

Status: accepted · 2026-10-14

Context

Search must return album art large enough for printing. A 51 mm art area at 300 dpi needs about 600 px. It must also return the artist and title, with no API key, because a static page cannot hide one.

The album search alone misses some well-known albums, such as Nirvana's Nevermind, which the song search finds.

Decision

Use the iTunes Search API (US store) as the only online source. Ask for albums and songs in one request (entity=album,song, 200 results) and group the songs under their albums. Request artwork at 1200 × 1200 px.

Alternatives

  • Deezer: no key, but art only up to 1000 px.
  • MusicBrainz + Cover Art Archive: open data, but limited to 1 request/s, and many releases have no art.
  • Several sources with fallback: better coverage, but more code and duplicates to merge.
  • Separate album and song requests, merged: two round trips, and no shared ranking to merge them by.

Consequences

  • Only the US catalogue is searched. Albums missing there need an upload.
  • The 1200 px URL is a URL pattern, not a documented API. If it stops working, the 100 px thumbnail would trigger the low-resolution warning.
  • A comma-separated entity list is not documented either. If it stops working, albums found only through their songs go missing again.
  • Each search downloads up to 200 results, about 33 KB compressed.
